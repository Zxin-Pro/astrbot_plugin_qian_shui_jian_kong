# astrbot_plugin_qian_shui_jian_kong 潜水监控

一个面向 AstrBot（v4.x，兼容 v3.5.19+）的**群潜水监控插件**：按目标群号监控成员活跃度，每日定时发布潜水排行榜，预警期自动 @ 警告，达到红线后按规则自动移出成员。未填写目标群号时插件不监控任何群。**所有参数均可在 AstrBot WebUI 插件配置面板中可视化修改，保存即热重载生效，无需改任何代码。**

## ✨ 功能特性

| 功能 | 说明 |
|---|---|
| 🔍 指定群监控 | 只有填写在 `groups_to_monitor` 中的群才会生效；留空时不监控任何群，避免误监控全部群 |
| 📊 每日潜水排行榜 | 每天 `08:00`（可配）自动推送：活跃人数、预警区人数、待处置人数、潜水 TOP 排行 |
| 🔔 预警 @ 警告 | 潜水天数 ≥ `阈值 - 预警天数` 时自动 @ 该成员提醒（同一成员 24h 内不重复打扰） |
| 🚪 自动移出群聊 | 开启 `enable_auto_kick` 后，达到红线直接按规则移出；关闭时只统计和预警 |
| ⭐ 白名单 | 全局白名单（WebUI 配置）+ 群级白名单（指令维护）合并生效：不警告不踢，排行榜中显示 ⭐ |
| 🧩 多群独立配置 | 每个群可单独覆盖阈值 / 预警天数 / 自动踢人相关设置 / 最终警告开关；未覆盖的项自动回落到全局配置 |
| 🛟 安全兜底 | 初始化后 24h 保护期不踢人；群主/群管理员不参与警告与踢出（OneBot 无法移出，避免无效评估）；机器人自身账号自动排除；每轮警告/评估限量防刷屏；踢出失败自动重试、连续 3 次失败放弃并提示检查机器人权限 |

## 📦 安装

1. 将本目录放入 AstrBot 的 `data/plugins/` 下（或通过 WebUI「插件管理 → 从仓库安装」填入本仓库地址）；
2. 在 WebUI 重载插件；
3. 确认已接入 **aiocqhttp** 平台适配器（NapCat / Lagrange.OneBot / LLOneBot / go-cqhttp 等 OneBot v11 协议端），且机器人在目标群拥有**管理员权限**（否则无法拉取成员列表与踢人）；

> 插件加载约 5～30 秒后自动完成群成员初始化（等待协议端连接就绪，带重试）。

## ⚙️ WebUI 可视化配置

> 📍 配置入口：WebUI 左侧 **「扩展」**（插件管理）页 → 找到「潜水监控」卡片 → 点击 **⚙ 齿轮图标（配置）** → 弹出配置对话框。修改后点击保存，AstrBot 会自动热重载本插件，**新配置立即生效**。（注意：左侧「配置」页是系统配置，插件参数在「扩展」页的插件卡片上。）

插件目录下的 `_conf_schema.json` 定义了全部配置项：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `threshold_days` | int | `7` | 全局默认斩杀线天数；每个群可在 WebUI 或 `/潜水 设置阈值` 中单独覆盖 |
| `warning_days` | int | `2` | 全局默认提前预警天数；每个群可在 WebUI 面板或 `/潜水 设置预警` 中单独覆盖 |
| `check_interval` | int | `3600` | 活跃检查间隔（秒），最小 60 |
| `daily_report_time` | string | `"08:00"` | 每日报告发送时间（24h 制 HH:MM） |
| `enable_auto_kick` | bool | `true` | 是否自动踢人；关闭后仍统计和预警，但不会定时移出成员 |
| `warn_before_kick` | bool | `true` | 踢人前先 @ 发送最终警告 |
| `groups_to_monitor` | list | `[]` | 要监控的群号列表；**留空 = 不监控任何群**，必须填写目标群号 |
| `whitelist` | list | `[]` | 全局白名单用户 ID：不警告不踢、排行显示 ⭐ |
| `report_top_n` | int | `10` | 排行榜最多显示人数 |
| `max_warns_per_round` | int | `0` | 每轮警告人数上限，**0 = 不限制**（预警区所有人都会被 @）；正数可在超大群限流防刷屏 |
| `max_kick_evals_per_round` | int | `0` | 每轮自动踢人人数上限，**0 = 不限制**；正数可控制单轮踢人数量 |
| `warn_template` | text | 内置文案 | 普通预警 @ 文案模板，支持占位符与多行 |
| `kick_notice_template` | text | 内置文案 | 移出通知文案模板，支持 `{name}`、`{uid}`、`{days}`、`{reason}`、`{decision}` 占位符与多行；留空使用内置默认文案 |
| `kill_warn_template` | text | 内置文案 | 斩杀预警文案模板，支持 `{count}`、`{threshold}`、`{group}` 占位符与多行；成员名单会以真实 @ 组件逐行追加 |

### 📝 自定义预警模板

在 WebUI 配置项 `warn_template` 中自定义预警文案（`text` 类型，支持多行）。占位符会在发送时自动替换：

| 占位符 | 含义 | 示例值 |
|---|---|---|
| `{name}` | 成员昵称/群名片 | 张三 |
| `{days}` | 已潜水时长 | 5.8 天 |
| `{remain}` | 距阈值剩余时长 | 1.2 天 |
| `{warn_line}` | 预警线天数 | 5 |
| `{threshold}` | 阈值天数 | 7 |
| `{group}` | 群号 | 123456789 |

示例（活跃群友好版）：

```
喂喂 {name}！你已经 {days} 没冒泡啦 🐟
潜水满 {threshold} 天会被请出群哦，聊两句复活一下吧～
```

说明：
- 消息发送时会**自动 @ 目标成员**，模板中无需写 @；
- 未知占位符（如 `{qq}`）会原样保留，不会报错；
- 各群可在群内用 KV 配置覆盖为不同文案（多群独立配置能力）；
- 留空则使用内置默认文案。

## 💬 指令

> 指令需以唤醒前缀（默认 `/`）触发；单独发送 `/潜水` 会显示自动生成的指令树。

| 指令 | 权限 | 说明 |
|---|---|---|
| `/潜水 查看 [群号]` | 所有人 | 查看潜水排行榜（群外查询需带群号且为管理员） |
| `/潜水 设置阈值 <天数> [群号]` | 管理员 | 设置该群斩杀线，每个群独立生效；WebUI 也可设置 |
| `/潜水 设置预警 <天数> [群号]` | 管理员 | 设置该群提前预警天数，每个群独立生效；WebUI 也可设置 |
| `/潜水 预警 [群号]` | 管理员 | 立即 @ 当前群已到预警线但尚未到踢人红线的成员 |
| `/潜水 斩杀预警 [群号]` | 管理员 | 使用自定义文案 @ 已到斩杀线但尚未移出的成员 |
| `/潜水 斩杀 [群号]` | 管理员 | 批量斩杀当前群所有已到斩杀线的成员：先发一条总体汇总消息（模板可自定义），统一踢出后等待 10 秒，再发送总结消息（模板可自定义，默认「已斩杀 N 位成员 请各位保持活跃～」） |
| `/潜水 白名单 添加/移除 <@用户或QQ号>` | 管理员 | 维护当前群的独立白名单 |
| `/潜水 白名单 查看` | 管理员 | 查看当前群白名单 |
| `/潜水 报告 [群号]` | 所有人 | 手动立即发送监测报告 |
| `/潜水 初始化 [群号]` | 管理员 | 重新拉取成员列表并初始化（保留历史活跃数据） |

## 🗄️ 数据存储

基于 AstrBot 的 `PluginKVStoreMixin`（`put_kv_data` / `get_kv_data` / `delete_kv_data`），数据保存在 AstrBot 内置数据库中，重启不丢失。核心结构：

```text
lurker:members:{群号}       -> {用户ID: {"first_seen", "last_message_time",
                                "username", "warned_at", "evaluated_at", "kick_fails"}}
lurker:group_config:{群号}  -> {群级覆盖配置, "whitelist": [...]}
lurker:group_meta:{群号}    -> {"initialized_at", "last_report_date", "member_count"}
lurker:index                -> {群号: {"platform_id", "group_name"}}
```

采用「内存读写 + 脏标记 + 批量落盘」设计：群消息高频更新只写内存，每 60 秒批量落盘一次，关键操作（初始化/踢出/改配置/卸载）即时落盘。

## ❓ FAQ

**Q: 为什么没有发送日报 / 没有踢人？**
A: 依次检查：机器人是否通过 aiocqhttp 接入且在线；机器人在该群是否有管理员权限；该群是否在 `groups_to_monitor` 名单内；报告时间为机器人服务器时区的本地时间（刚装好的插件只会在报告时间 ±30 分钟窗口内首发，之后每次重启错过时刻会自动补发）；`/潜水 查看` 看群数据是否已初始化。

**Q: 为什么刚装好插件，就有人被 @ 警告 / 排行榜里出现很高的潜水天数？**
A: 新成员首次纳管时，优先读取 OneBot 提供的 `last_sent_time` 作为最后发言时间；没有有效历史记录时才从当前时间起算。已经纳管过的成员会保留插件记录中的最后发言时间，重新初始化不会重置计时。

**Q: 为什么群主和管理员没有被警告/踢出？**
A: 设计行为。OneBot v11 无法移出群主/管理员，因此插件会自动跳过这两类角色，避免无效操作和群内刷屏。

**Q: 会误踢人吗？**
A: 有多层保护：初始化 24h 保护期；预警期先 @ 警告；支持关闭自动踢人；踢出前可发最终通牒；白名单、群主和管理员完全豁免。

**Q: 支持其他平台（QQ 官方 API、微信等）吗？**
A: 群成员列表与踢人依赖 OneBot v11 的群管理接口，目前仅 aiocqhttp 协议端支持；其他平台消息监听与统计不受影响，但无法自动初始化与踢人（日志会提示）。
