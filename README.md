# astrbot_plugin_lurker_watcher 潜水监测助手

一个面向 AstrBot（v4.x，兼容 v3.5.19+）的**群潜水监测插件**：自动监控全体群成员活跃度，每日定时发布潜水排行榜，预警期自动 @ 警告，达到阈值后结合 **LLM 智能决策**自动移出长期潜水成员。**所有参数均可在 AstrBot WebUI 插件配置面板中可视化修改，保存即热重载生效，无需改任何代码。**

## ✨ 功能特性

| 功能 | 说明 |
|---|---|
| 🔍 全员自动监控 | 插件加载后自动拉取机器人所在的所有群（OneBot v11 协议端），将全部成员纳入监控；机器人新加入的群收到首条消息时也会自动纳管 |
| 📊 每日潜水排行榜 | 每天 `08:00`（可配）自动推送：活跃人数、预警区人数、待处置人数、潜水 TOP 排行 |
| 🔔 预警 @ 警告 | 潜水天数 ≥ `阈值 - 预警天数` 时自动 @ 该成员提醒（同一成员 24h 内不重复打扰） |
| ⚖️ LLM 智能踢人决策 | 超过阈值后先让大模型结合成员数据（纳管时长、潜水天数等）裁决是否真的要踢，输出 JSON 结论与理由；LLM 不可用时**安全第一**，本轮跳过次日重评 |
| 🚪 自动移出群聊 | LLM 确认（或关闭 LLM 决策时按规则）后：可选发送最终通牒 → 调用平台接口移出 → 群内公示移出通知 |
| ⭐ 白名单 | 全局白名单（WebUI 配置）+ 群级白名单（指令维护）合并生效：不警告不踢，排行榜中显示 ⭐ |
| 🧩 多群独立配置 | 每个群可单独覆盖阈值 / 预警天数 / LLM 决策开关 / 最终警告开关；未覆盖的项自动回落到全局配置 |
| 🛟 安全兜底 | 初始化后 24h 保护期不踢人；群主/群管理员不参与警告与踢出（OneBot 无法移出，避免无效评估）；机器人自身账号自动排除；每轮警告/评估限量防刷屏；踢出失败自动重试、连续 3 次失败放弃并提示检查机器人权限 |

## 📦 安装

1. 将本目录放入 AstrBot 的 `data/plugins/` 下（或通过 WebUI「插件管理 → 从仓库安装」填入本仓库地址）；
2. 在 WebUI 重载插件；
3. 确认已接入 **aiocqhttp** 平台适配器（NapCat / Lagrange.OneBot / LLOneBot / go-cqhttp 等 OneBot v11 协议端），且机器人在目标群拥有**管理员权限**（否则无法拉取成员列表与踢人）；
4. 如需 LLM 智能决策，请在 WebUI「服务商配置」中配置好任一 LLM 提供商。

> 插件加载约 5～30 秒后自动完成群成员初始化（等待协议端连接就绪，带重试）。

## ⚙️ WebUI 可视化配置

> 📍 配置入口：WebUI 左侧 **「扩展」**（插件管理）页 → 找到「潜水监测助手」卡片 → 点击 **⚙ 齿轮图标（配置）** → 弹出配置对话框。修改后点击保存，AstrBot 会自动热重载本插件，**新配置立即生效**。（注意：左侧「配置」页是系统配置，插件参数在「扩展」页的插件卡片上。）

插件目录下的 `_conf_schema.json` 定义了全部配置项：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `threshold_days` | int | `7` | 潜水天数阈值：连续无发言达到该天数后进入踢人评估 |
| `warning_days` | int | `2` | 提前预警天数：潜水 ≥ 阈值-预警天数时 @ 警告 |
| `check_interval` | int | `3600` | 活跃检查间隔（秒），最小 60 |
| `daily_report_time` | string | `"08:00"` | 每日报告发送时间（24h 制 HH:MM） |
| `enable_llm_decision` | bool | `true` | 启用 LLM 智能决策；关闭后达到阈值按规则直接踢出 |
| `warn_before_kick` | bool | `true` | 踢人前先 @ 发送最终警告 |
| `groups_to_monitor` | list | `[]` | 要监控的群号列表；**留空 = 监控所有群** |
| `whitelist` | list | `[]` | 全局白名单用户 ID：不警告不踢、排行显示 ⭐ |
| `report_top_n` | int | `10` | 排行榜最多显示人数 |
| `max_warns_per_round` | int | `0` | 每轮警告人数上限，**0 = 不限制**（预警区所有人都会被 @）；正数可在超大群限流防刷屏 |
| `max_kick_evals_per_round` | int | `0` | 每轮踢人评估人数上限，**0 = 不限制**；正数可控制 LLM 调用量 |
| `warn_template` | text | 内置文案 | 预警 @ 警告文案模板，支持占位符与多行（见下方「自定义预警模板」） |

### 📝 自定义预警模板

在 WebUI 配置项 `warn_template` 中自定义预警文案（`text` 类型，支持多行）。占位符会在发送时自动替换：

| 占位符 | 含义 | 示例值 |
|---|---|---|
| `{name}` | 成员昵称/群名片 | 张三 |
| `{days}` | 已潜水时长 | 5.8 天 |
| `{remain}` | 距阈值剩余时长 | 1.2 天 |
| `{warn_line}` | 预警线天数 | 5 |
| `{threshold}` | 阈值天数 | 7 |
| `{group}` | 群号 | 123456789 |

示例（活跃群友好版）：

```
喂喂 {name}！你已经 {days} 没冒泡啦 🐟
潜水满 {threshold} 天会被请出群哦，聊两句复活一下吧～
```

说明：
- 消息发送时会**自动 @ 目标成员**，模板中无需写 @；
- 未知占位符（如 `{qq}`）会原样保留，不会报错；
- 各群可在群内用 KV 配置覆盖为不同文案（多群独立配置能力）；
- 留空则使用内置默认文案。

## 💬 指令

> 指令需以唤醒前缀（默认 `/`）触发；单独发送 `/lurker` 会显示自动生成的指令树。

| 指令 | 权限 | 说明 |
|---|---|---|
| `/lurker list [群号]` | 所有人 | 查看潜水排行榜（群外查询需带群号且为管理员） |
| `/lurker set_threshold <天数> [群号]` | 管理员 | 设置该群阈值（写入群独立配置） |
| `/lurker set_warning <天数> [群号]` | 管理员 | 设置该群提前预警天数 |
| `/lurker whitelist add/remove <@用户或QQ号>` | 管理员 | 维护当前群的独立白名单 |
| `/lurker whitelist show` | 管理员 | 查看当前群白名单 |
| `/lurker report [群号]` | 所有人 | 手动立即发送监测报告 |
| `/lurker init [群号]` | 管理员 | 重新拉取成员列表并初始化（保留历史活跃数据） |

## 🤖 LLM 工具：decide_kick

本插件向 LLM 注册了 `decide_kick` 工具（参数：`group_id` / `user_id` / `action=kick|keep` / `reason`）：

* **自动决策**：定时检查达到阈值的成员时，插件内部调用当前 LLM 提供商对每位成员单独裁决（要求严格输出 JSON），`kick` 则执行移出，`keep` 则保留并记录理由；
* **会话裁决**：管理员在群内/私聊对话中要求机器人「处置某位潜水成员」时，LLM 可调用该工具执行实际操作（工具内部校验操作者必须是 AstrBot 管理员，防止普通成员借 LLM 踢人）；
* 未配置 LLM 提供商时：自动决策会跳过该成员（日志提示），可关闭 `enable_llm_decision` 改为规则直接踢出。

## 🗄️ 数据存储

基于 AstrBot 的 `PluginKVStoreMixin`（`put_kv_data` / `get_kv_data` / `delete_kv_data`），数据保存在 AstrBot 内置数据库中，重启不丢失。核心结构：

```text
lurker:members:{群号}       -> {用户ID: {"first_seen", "last_message_time",
                                "username", "warned_at", "evaluated_at", "kick_fails"}}
lurker:group_config:{群号}  -> {群级覆盖配置, "whitelist": [...]}
lurker:group_meta:{群号}    -> {"initialized_at", "last_report_date", "member_count"}
lurker:index                -> {群号: {"platform_id", "group_name"}}
```

采用「内存读写 + 脏标记 + 批量落盘」设计：群消息高频更新只写内存，每 60 秒批量落盘一次，关键操作（初始化/踢出/改配置/卸载）即时落盘。

## ❓ FAQ

**Q: 为什么没有发送日报 / 没有踢人？**
A: 依次检查：机器人是否通过 aiocqhttp 接入且在线；机器人在该群是否有管理员权限；该群是否在 `groups_to_monitor` 名单内；报告时间为机器人服务器时区的本地时间（刚装好的插件只会在报告时间 ±30 分钟窗口内首发，之后每次重启错过时刻会自动补发）；`/lurker list` 看群数据是否已初始化。

**Q: 为什么刚装好插件，就有人被 @ 警告 / 排行榜里出现很高的潜水天数？**
A: v1.0.0/v1.0.1 的旧版行为（已废弃）。v1.0.2 起，**首次纳管一律从当前时间起算**：机器人入群前的历史数据（协议端 last_sent_time）不可靠且无法核实，不再作为潜水天数依据；只有机器人自己观察到的持续沉默才会累计潜水天数。装好插件后，所有成员从零开始计数，绝不会再出现"一装好就 @ 人"。

**Q: 为什么群主和管理员没有被警告/踢出？**
A: 设计行为。OneBot v11 无法移出群主/管理员，对他们发起评估只会白白消耗 LLM 调用并在群里刷失败通知，因此插件自动跳过这两类角色。

**Q: 会被 LLM 乱踢人吗？**
A: 有多层保护：初始化 24h 保护期；预警期先 @ 警告给用户机会；LLM 裁决要求输出理由且倾向保留；LLM 不可用/输出异常时本轮不踢；踢出前可发最终通牒；白名单完全豁免。

**Q: 支持其他平台（QQ 官方 API、微信等）吗？**
A: 群成员列表与踢人依赖 OneBot v11 的群管理接口，目前仅 aiocqhttp 协议端支持；其他平台消息监听与统计不受影响，但无法自动初始化与踢人（日志会提示）。
